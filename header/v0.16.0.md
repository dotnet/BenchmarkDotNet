BenchmarkDotNet v0.16.0 is the biggest release in the project's history: 298 merged pull requests from 37 contributors, resolving 96 issues.
It reworks the engine around async, improves measurement accuracy, and redesigns the runtime and toolchain model.
It is also a major release with many **breaking changes**, so please read the [Breaking changes](#breaking-changes) section before upgrading.

## Highlights

### Async-first engine

* Async benchmarks are now actually awaited instead of being synchronously blocked on ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)). When started with the new async APIs (`BenchmarkRunner.RunAsync`, `BenchmarkSwitcher.Run*Async`), async benchmarks now work in-process on a UI thread, which used to deadlock. The synchronous `Run` APIs still block the UI thread and can deadlock.
* `[IterationSetup]` and `[IterationCleanup]` support async methods ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)).
* Benchmarks can return custom awaitable types, and `[AsyncCallerType]` overrides the return type of the async method that calls the benchmark ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)).
* New `BenchmarkRunner.RunAsync` and `BenchmarkSwitcher.Run*Async` APIs with cooperative cancellation, and a `[BenchmarkCancellation]` `CancellationToken` field or property lets a benchmark respond to it ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)). The synchronous `Run` APIs take a `CancellationToken` too ([#3213](https://github.com/dotnet/BenchmarkDotNet/pull/3213)).
* Benchmarks that return `IAsyncEnumerable<T>` (or any type that works with `await foreach`) are now enumerated to completion on every invocation, instead of only measuring the call that creates the enumerable ([#3124](https://github.com/dotnet/BenchmarkDotNet/pull/3124)), and `[ParamsSource]`/`[ArgumentsSource]` can return `IAsyncEnumerable<T>` ([#3248](https://github.com/dotnet/BenchmarkDotNet/pull/3248)).
* `[ConsumeTasksSynchronously]` / `--consumeTasksSynchronously` brings back the previous `GetAwaiter().GetResult()` behavior, for comparing results with older versions ([#3142](https://github.com/dotnet/BenchmarkDotNet/pull/3142)).
* Experimental support for runtime-async benchmarks with the in-process emit toolchain ([#3284](https://github.com/dotnet/BenchmarkDotNet/pull/3284)).
* Ctrl+C now cancels the run gracefully instead of killing the process, and pressing it again forces an abort ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)).

### Accuracy

* The generated benchmark code was rewritten ([#2336](https://github.com/dotnet/BenchmarkDotNet/pull/2336)). The benchmark is now called directly instead of through a delegate, its return value is discarded instead of being passed to a `Consumer`, the overhead method always returns `void`, and a new assembly weaver applies `MethodImplOptions.NoInlining` to benchmark methods automatically.
* Overhead evaluation is now **disabled by default** ([#3007](https://github.com/dotnet/BenchmarkDotNet/pull/3007)). On runtimes where call overhead is still measurable, such as pure interpreters, you can turn it back on with `[EvaluateOverhead]`, or with the new `--evaluateOverhead true` option ([#3058](https://github.com/dotnet/BenchmarkDotNet/pull/3058)).
* The JIT stage now pushes the benchmark through every JIT tier before the pilot and warmup stages, so measurements no longer start on unoptimized code. A slow first invocation, such as a static constructor, no longer makes the pilot stage pick a single invocation per iteration ([#2806](https://github.com/dotnet/BenchmarkDotNet/pull/2806)). It follows tier promotion by listening to the runtime's JIT events ([#3169](https://github.com/dotnet/BenchmarkDotNet/pull/3169)).
* Out-of-process CoreCLR runs now set `TC_CallCountingDelayMs=0` (except with `RunStrategy.ColdStart`) ([#2806](https://github.com/dotnet/BenchmarkDotNet/pull/2806)), and disable on-stack replacement (OSR) with the default `Throughput` strategy, which keeps the JIT stage short ([#3201](https://github.com/dotnet/BenchmarkDotNet/pull/3201)). Environment variables set on the job still take precedence.

### Runtimes and toolchains

* Runtimes and toolchains were redesigned ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)):
  * Runtimes no longer need a BenchmarkDotNet update for each new .NET version. `RuntimeMoniker` is now a set of string constants backed by `Runtime.Parse`/`Runtime.TryParse`, and `CoreRuntime.From(version)` creates any .NET version.
  * A job's runtime and toolchain are now coupled: `WithToolchain` sets the runtime, and `WithRuntime` with a different runtime clears an explicitly set toolchain. The new `BDN1800` analyzer and code fix flag jobs that set both.
  * There is now one runtime type per VM/JIT/interpreter/AOT configuration, such as `MonoWasmRuntime`, `MonoWasmAotRuntime`, `CoreWasmRuntime` and `MonoCoreRuntime`, and all toolchains are created with `*Toolchain.From(...)`.
  * Jobs that differ only in toolchain settings are no longer merged, and the differing settings are shown in the summary table.
* .NET 11 and .NET 12 support ([#2911](https://github.com/dotnet/BenchmarkDotNet/pull/2911), [#3253](https://github.com/dotnet/BenchmarkDotNet/pull/3253)).
* WebAssembly:
  * Benchmarks run on Windows and on Node.js, and you can supply a custom startup script with `--wasmMainJsTemplate`. `--wasmEngine` accepts an executable on `PATH`, such as `node` ([#3020](https://github.com/dotnet/BenchmarkDotNet/pull/3020)).
  * The new `--wasmProcessTimeout` option sets how long a WASM benchmark process may run before it is killed, which used to be a fixed 10 minutes ([#3026](https://github.com/dotnet/BenchmarkDotNet/pull/3026)).
  * Experimental CoreCLR-on-WASM support, selected with `--runtimes corewasm11.0` ([#2998](https://github.com/dotnet/BenchmarkDotNet/pull/2998), [#3018](https://github.com/dotnet/BenchmarkDotNet/pull/3018), [#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
  * `MemoryDiagnoser` works on WASM ([#3040](https://github.com/dotnet/BenchmarkDotNet/pull/3040)).
* New composite ReadyToRun toolchain (`--runtimes r2r10.0`), which can use a local runtime pack and crossgen2 through `--customRuntimePack` and `--AOTCompilerPath` ([#2967](https://github.com/dotnet/BenchmarkDotNet/pull/2967)).
* NativeAOT: `--ilcPackages` accepts several paths and creates one job per path, so local builds of the runtime can be compared against each other. The first path is the baseline ([#3288](https://github.com/dotnet/BenchmarkDotNet/pull/3288)).
* Generated projects now reference the same assemblies as your project, so benchmarks can use plain DLL references (`<Reference Include="...">`) ([#2508](https://github.com/dotnet/BenchmarkDotNet/pull/2508)).
* Generated projects now build when a `Directory.Build.props` sets `TargetFrameworks`. Previously the inherited `TargetFrameworks` overrode the generated project's target framework, and the build failed ([#2508](https://github.com/dotnet/BenchmarkDotNet/pull/2508)).
* Generated projects use much shorter paths under a `.bdn` folder, which avoids the Windows `MAX_PATH` limit ([#3274](https://github.com/dotnet/BenchmarkDotNet/pull/3274)). The new `--freshPackages` option restores into an empty folder so that locally rebuilt packages are picked up.
* In-process toolchains:
  * `InProcessSettings` can run the benchmark on the calling thread ([#2938](https://github.com/dotnet/BenchmarkDotNet/pull/2938)).
  * `InProcessNoEmitToolchain` supports pointer, by-ref, `ValueTask` and ref struct returns ([#2315](https://github.com/dotnet/BenchmarkDotNet/pull/2315)), and you can plug in your own benchmark actions with `IBenchmarkActionFactory` ([#3063](https://github.com/dotnet/BenchmarkDotNet/pull/3063)).
  * Environment info is now reported for in-process runs ([#3267](https://github.com/dotnet/BenchmarkDotNet/pull/3267)).
  * In-process runs no longer lower the process and thread priority after a failed attempt to raise it ([#3282](https://github.com/dotnet/BenchmarkDotNet/pull/3282)).
* Mobile platforms: the samples were ported to .NET MAUI ([#2929](https://github.com/dotnet/BenchmarkDotNet/pull/2929)). On iOS and Mac Catalyst, as already on Android, the default artifacts folder is now in a writable location, so benchmarks no longer fail with an access-denied error ([#2930](https://github.com/dotnet/BenchmarkDotNet/pull/2930)).

### Diagnosers

* Diagnosers can now run inside the benchmark process through `IInProcessDiagnoser` ([#2843](https://github.com/dotnet/BenchmarkDotNet/pull/2843)). Custom diagnosers can return the new `RunMode.ExtraIteration` to collect statistics in the extra iteration that `MemoryDiagnoser` uses, signalled by `BeforeExtraIteration`/`AfterExtraIteration`. `ThreadingDiagnoser` and `ExceptionDiagnoser` are now built on this instead of being hard-coded into the engine ([#2934](https://github.com/dotnet/BenchmarkDotNet/pull/2934)).
* `DisassemblyDiagnoser` now runs inside the benchmark process by default (`runInHost` restores the previous behavior), which makes it work on macOS ([#2843](https://github.com/dotnet/BenchmarkDotNet/pull/2843)).
* Fixed an `EventPipeProfiler` hang at the end of a run ([#3072](https://github.com/dotnet/BenchmarkDotNet/pull/3072)).
* `[EventPipeProfiler]` accepts `performExtraBenchmarksRun` ([#3075](https://github.com/dotnet/BenchmarkDotNet/pull/3075)).

### Configuration, command line and exporters

* Job categories: set them with `job.WithCategory(...)` or the `Categories` property on job attributes, and filter with `[JobCategoryFilter]` or `--anyJobCategories` ([#3239](https://github.com/dotnet/BenchmarkDotNet/pull/3239)).
* `--list` has a new `json` output format alongside `flat` and `tree`, for tools that consume the list of benchmarks. Without running any benchmarks, it prints details for each benchmark case: a unique ID, filter name, full name, categories, job characteristics and source location ([#3227](https://github.com/dotnet/BenchmarkDotNet/pull/3227)).
* `--exporters` accepts custom `IExporter` types by assembly-qualified name, and accepts `OpenMetrics` ([#3212](https://github.com/dotnet/BenchmarkDotNet/pull/3212), [#3137](https://github.com/dotnet/BenchmarkDotNet/pull/3137)). The OpenMetrics exporter now includes allocated bytes ([#3138](https://github.com/dotnet/BenchmarkDotNet/pull/3138)).
* `WithTitle(...)` / `--title` sets the name of joined summaries and their exported files ([#3214](https://github.com/dotnet/BenchmarkDotNet/pull/3214)).
* `DefaultConfig.SetCustomConfig(...)` replaces the default global config, which is useful with the test adapter ([#3051](https://github.com/dotnet/BenchmarkDotNet/pull/3051)).
* MSBuild arguments ([#3055](https://github.com/dotnet/BenchmarkDotNet/pull/3055)):
  * `new MsBuildArgument(value, escapeSpecialCharacters: true)` escapes MSBuild special characters such as `;`.
  * The new `MsBuildProperty(name, params values)` creates a `/p:name=value` argument, joining multiple values with `;` and escaping them, for example `new MsBuildProperty("DefineConstants", "TEST1", "TEST2")`.
* The environment summary shows total and available RAM, and the memory type and frequency ([#3038](https://github.com/dotnet/BenchmarkDotNet/pull/3038), [#3281](https://github.com/dotnet/BenchmarkDotNet/pull/3281)).
* Jobs are sorted in numeric order by default, so `.NET 8.0` comes before `.NET 10.0`. Use `JobOrderPolicy.Ordinal` for the previous order ([#2933](https://github.com/dotnet/BenchmarkDotNet/pull/2933)).
* Invalid benchmark declarations are now reported as validation errors instead of aborting discovery ([#3268](https://github.com/dotnet/BenchmarkDotNet/pull/3268)).
* Ambiguous type names are qualified with their namespace in the interactive benchmark selection ([#3211](https://github.com/dotnet/BenchmarkDotNet/pull/3211)).

### Packages

* The codebase now has nullable reference type annotations ([#2815](https://github.com/dotnet/BenchmarkDotNet/issues/2815)).
* Builds with .NET SDKs older than 6.0 no longer get analyzer load warnings ([#3264](https://github.com/dotnet/BenchmarkDotNet/pull/3264)).
* The `netstandard2.0` and `net6.0` builds of BenchmarkDotNet no longer contain a polyfill of `UnsafeAccessorAttribute`, which could fool source generators, such as the System.Text.Json one, into emitting code that needs .NET 8 or later ([#3306](https://github.com/dotnet/BenchmarkDotNet/pull/3306)).

## Breaking changes

Third-party diagnosers and exporters built against 0.15.x are not binary compatible with 0.16.0, because their interfaces became async (see [Extensibility API changes](#extensibility-api-changes)). They fail at runtime with a `TypeLoadException` until they are updated, even if you never wrote one yourself. This includes the Visual Studio profiler package `Microsoft.VisualStudio.DiagnosticsHub.BenchmarkDotNetDiagnosers` that the Visual Studio *Benchmark Project* template references ([#3083](https://github.com/dotnet/BenchmarkDotNet/issues/3083)).

### Behavior changes

* Async benchmarks are now awaited, so their results may differ from previous versions ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)). Use `--consumeTasksSynchronously` to compare with older results ([#3142](https://github.com/dotnet/BenchmarkDotNet/pull/3142)).
* Overhead evaluation is disabled by default ([#3007](https://github.com/dotnet/BenchmarkDotNet/pull/3007)).
* `WithRuntime` with a different runtime clears an explicitly set toolchain, and `WithToolchain` overwrites the runtime ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* Jobs are compared by value, so jobs that used to be merged because they looked the same in the summary now run separately ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* `Runtime.Name` no longer includes the version. `ToString()` still does ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* `--cli <path>` on its own no longer creates a job ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* WASM runtimes are selected with `--runtimes monowasm8.0`, `monowasmaot8.0` or `corewasm11.0`. The old `wasm` and `wasmnet80`-style monikers are no longer accepted ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* A benchmark type with a `required` member that is not a `[Params*]` or `[BenchmarkCancellation]` member is now rejected by validation. Out-of-process toolchains already failed to build such types, but the in-process toolchains used to run them ([#3248](https://github.com/dotnet/BenchmarkDotNet/pull/3248)).
* A single-parameter benchmark no longer accepts an `[ArgumentsSource]` that returns `IEnumerable<object[]>`, unless the parameter itself is `object[]` ([#3265](https://github.com/dotnet/BenchmarkDotNet/pull/3265)).
* Generated projects are built under `.bdn` in the project directory, and the generated assembly is named `<YourAssembly>-gen` ([#3274](https://github.com/dotnet/BenchmarkDotNet/pull/3274)).
* A generated project directory is kept after a failed build only when `--keepFiles` is set ([#3046](https://github.com/dotnet/BenchmarkDotNet/pull/3046)).

### Removed APIs and options

* Obsolete APIs removed ([#2904](https://github.com/dotnet/BenchmarkDotNet/pull/2904)):
  * `[ClrJob]`, `[CoreJob]`, `[DryClrJob]`, `[DryCoreJob]`, `[DryMonoJob]` and `[Encoding]`.
  * `BaselineScaledColumn`, and the CoreRT runtime and toolchain.
  * The `ManualConfig.Add(...)`, `IConfig.With(...)` and `Job.With(...)` overloads. Use the `AddX`/`WithX` methods instead.
  * NuGet references: `Job.WithNuGet(...)`, `InfrastructureMode.NuGetReferences`, `NuGetReference` and `NuGetReferenceList`.
  * `BenchmarkRunner.RunSource`/`RunUrl`, and `BenchmarkConverter.SourceToBenchmarks`/`UrlToBenchmarks`.
* `JobOrderPolicy.Default` was replaced by `JobOrderPolicy.Ordinal`, and `Numeric` is now the default ([#2933](https://github.com/dotnet/BenchmarkDotNet/pull/2933)).
* `Runtime.IsAOT`, `[AotFilter]`, `CustomRuntime`, the MonoAotLLVM runtime and toolchain (`MonoAotLLVMRuntime`, `MonoAotLLVMToolChain`, `MonoAotCompilerMode`), `ClrRuntime.CreateForLocalFullNetFrameworkBuild`, `NativeAotRuntime.GetCurrentVersion()`, `NativeAotToolchainBuilder`, `CustomDotNetCliToolchainBuilder` and `RuntimeValidator` removed ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)). Code that checked `Runtime.IsAOT`, or used `[AotFilter]`, can check the runtime type instead, for example `runtime is NativeAotRuntime`. NativeAOT toolchains are now created with `CsProjNativeAotToolchain.From(runtime, new NativeAotSettings { ... })`.
* Command line options removed: `--clrVersion` and `--AOTCompilerMode` ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)), and `--wasmDataDir` ([#3020](https://github.com/dotnet/BenchmarkDotNet/pull/3020)). `--customRuntimePack` no longer applies to WASM, and `--AOTCompilerPath` no longer applies to MonoAotLLVM; both are now used only by ReadyToRun ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
* `--noOverheadEvaluation` was replaced by `--evaluateOverhead true|false` ([#3058](https://github.com/dotnet/BenchmarkDotNet/pull/3058)).
* NativeAOT for .NET 6 removed: `RuntimeMoniker.NativeAot60`, `NativeAotRuntime.Net60` and `NativeAotToolchain.Net60` ([#3223](https://github.com/dotnet/BenchmarkDotNet/pull/3223)).
* `DeadCodeEliminationHelper.KeepAliveWithoutBoxingReadonly` removed, and the `ref T` overload of `KeepAliveWithoutBoxing` now takes `in T` ([#3125](https://github.com/dotnet/BenchmarkDotNet/pull/3125)).
* The NativeAOT toolchain builder's `UseTempFolderForRestore` was replaced by `DotNetCliSettings.UseFreshPackages` and `--freshPackages`, which apply to all CsProj toolchains ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232), [#3274](https://github.com/dotnet/BenchmarkDotNet/pull/3274)).
* `ShadowCopyValidator` removed; the original assembly is now resolved instead ([#3257](https://github.com/dotnet/BenchmarkDotNet/pull/3257)).
* `IParam`, `ArrayParam<T>`, `EnumParam`, `ParameterDefinitions`, `ParameterDefinition.Values` and `ParameterInstance.ToSourceCode()` removed in favor of `ParameterValue`/`ParameterValues` ([#3248](https://github.com/dotnet/BenchmarkDotNet/pull/3248)).
* `InvalidBenchmarkDeclarationException` removed. `BenchmarkRunInfo` is sealed, its constructors are internal, and it is modified with `WithBenchmarks`/`WithConfig` ([#3268](https://github.com/dotnet/BenchmarkDotNet/pull/3268)).

### Toolchain and runtime API changes ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232))

* `Job.Environment.Runtime` moved to `Job.Infrastructure.Runtime`, next to the toolchain.
* `RuntimeMoniker` is now a static class of `string` constants. `[SimpleJob(RuntimeMoniker.Net80)]` still compiles, but code that uses `RuntimeMoniker` as a type (variables, parameters, enum comparisons) needs updating. Removed members: `HostProcess`, `NotRecognized`, `NetCoreApp50`, `MonoAOTLLVM*` and `WasmNet80`/`90`/`10_0` (now `MonoWasm*`/`MonoWasmAot*`); `Wasm` and `WasmNet50`/`60`/`70` were removed in [#3010](https://github.com/dotnet/BenchmarkDotNet/pull/3010). The job attributes now take `string` monikers, so assemblies compiled against older versions must be recompiled.
* `Runtime.RuntimeMoniker` and `Runtime.MsBuildMoniker` were replaced by `Runtime.Version`. Custom runtimes no longer pass a moniker and name to the base constructor; they implement the abstract `Name`, `Version` and `GetDefaultToolchain` members.
* `IToolchain.Name` was replaced by `IToolchain.Runtime`. `BuildPartition.IsNativeAot` was removed, and `BuildPartition.IsWasm` was removed in [#2951](https://github.com/dotnet/BenchmarkDotNet/pull/2951).
* `WasmRuntime` is now an abstract base for `MonoWasmRuntime`, `MonoWasmAotRuntime` and `CoreWasmRuntime`; its engine settings moved to `WasmSettings`. .NET on the Mono VM moved to `MonoCoreRuntime` (`MonoRuntime.Mono80` → `MonoCoreRuntime.Net80`), and Mono AOT moved to `MonoAotRuntime`. The `MonoRuntime` custom path, AOT arguments and BCL path moved to `MonoSettings`/`MonoAotSettings`.
* `CoreRuntime.CreateForNewVersion(...)` was replaced by `CoreRuntime.From(Version, string? platform = null)`.
* Toolchains were renamed to `[BuildType][Runtime]Toolchain` and are created with `From(...)`:

  | Before | After |
  |---|---|
  | `CsProjCoreToolchain` | `CsProjCoreToolchain` (namespace `BenchmarkDotNet.Toolchains.NetCoreApp`) |
  | `CsProjCoreToolchain.From(settings)` | `CsProjCoreToolchain.From(runtime, settings)` |
  | `CsProjClassicNetToolchain` | `CsProjFrameworkToolchain` (namespace `BenchmarkDotNet.Toolchains.Framework`) |
  | `RoslynToolchain.Instance` | `RoslynFrameworkToolchain.Default` / `RoslynMonoToolchain.Default` |
  | `new CoreRunToolchain(...)` | `CoreRunToolchain.From(new CoreRunSettings { ... })` |
  | `NativeAotToolchain` | `CsProjNativeAotToolchain` |
  | `MonoToolchain` | `CsProjMonoCoreToolchain` |
  | `MonoAotToolchain` | `RoslynMonoAotToolchain` |
  | `WasmToolchain` | `CsProjMonoWasmToolchain` / `CsProjMonoWasmAotToolchain` / `CsProjCoreWasmToolchain` |

* `NetCoreAppSettings` moved to `BenchmarkDotNet.Toolchains.NetCoreApp` and is now a record with `init` properties (`CliPath`, `PackagesPath`, …) using `FileInfo`/`DirectoryInfo`. The per-version presets (`NetCoreAppSettings.NetCoreApp80`, …), the `With*` methods and `RuntimeFrameworkVersion`/`CustomRuntimePack`/`AOTCompilerPath` were removed; the target framework comes from the runtime. The other toolchains take their own settings records, such as `NativeAotSettings` and `WasmSettings`.
* Runtimes no longer implement `IEquatable<T>`; runtime equality is still value-based through `Equals(object)`. All toolchains now compare by value through `Equals(object)`; in 0.15.8 only `CsProjCoreToolchain` and `MonoToolchain` did.

### Extensibility API changes

* Async interfaces ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958)):
  * `IHost.SendSignal` → `SendSignalAsync`, plus new `CancellationToken` and `Yield()` members.
  * `IEngine.Run` → `RunAsync`, and `IExecutor.Execute` → `ExecuteAsync`.
  * `IBuilder.Build` → `BuildAsync`.
  * `IDiagnoser.Handle` → `HandleAsync`.
  * `Validate` → `ValidateAsync`, which returns `IAsyncEnumerable<ValidationError>`, on `IValidator`, `IDiagnoser` and `IToolchain`.
  * `IExporter.ExportToLog`/`ExportToFiles` → `ExportAsync`. Custom exporters that derive from `ExporterBase` now override `ExportAsync(Summary, CancelableStreamWriter, CancellationToken)` instead of `ExportToLog`.
  * `RunResults.Print` and `BenchmarkId.ToArguments` were removed.
  * `EngineParameters` workload/overhead delegates are now `Func<long, IClock, ValueTask<ClockSpan>>`, and the setup/cleanup delegates are `Func<ValueTask>`.
  * Host/benchmark IPC now uses TCP loopback instead of anonymous pipes.
* Generators were merged into builders ([#3256](https://github.com/dotnet/BenchmarkDotNet/pull/3256)):
  * `IGenerator`, `IToolchain.Generator`, `GenerateResult`, `BenchmarkReport.GenerateResult` and `DotNetCliPublisher`, `CoreRunPublisher` and `MonoPublisher` were removed.
  * `GeneratorBase` → `BuilderBase`; `CsProjGenerator` → `CsProjBuilder`, `CoreRunGenerator` → `CoreRunBuilder`, `WasmGenerator` → `CsProjWasmBuilder`, and the Roslyn `Generator`/`Builder` pair → `RoslynBuilder` ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232), [#3256](https://github.com/dotnet/BenchmarkDotNet/pull/3256)). The other generators were removed or made internal.
  * `IBuilder.BuildAsync` takes the root artifacts folder path instead of a `GenerateResult`. `IBuilder` gains `GetSupportsConcurrency`, and `DotNetCliBuilder` is now abstract.
* Engine ([#2806](https://github.com/dotnet/BenchmarkDotNet/pull/2806), [#2937](https://github.com/dotnet/BenchmarkDotNet/pull/2937)):
  * `IEngine` now has only `RunAsync`, which calls `GlobalSetup`/`GlobalCleanup` itself. `Engine` and `IEngine` are no longer `IDisposable`, and `Engine` no longer exposes its parameters as public properties.
  * `IEngineFactory.CreateReadyToRun` → `Create`.
  * `RunStrategy.NeedsJitting()` was removed.
* Threading and exception statistics are now collected by in-process diagnosers ([#2934](https://github.com/dotnet/BenchmarkDotNet/pull/2934)):
  * `ThreadingStats` was removed.
  * `ThreadingStats` and `ExceptionFrequency` were removed from `RunResults` and `DiagnoserResults`, along with `DiagnoserResults.TotalOperations`.
  * `ImmutableConfig.HasThreadingDiagnoser()`/`HasExceptionDiagnoser()`/`HasExtraStatsDiagnoser()` were removed.
* `DotNetCliCommand`: `RestoreThenBuild`/`RestoreThenBuildThenPublish` and `Restore`/`Build`/`BuildNoRestore`/`Publish`/`PublishNoRestore` were replaced by `RestoreThenBuildAsync`/`BuildAsync`/`PublishAsync`, which return `Task<BuildResult>`, and `DotNetCliCommandExecutor.Execute` → `ExecuteAsync` ([#2958](https://github.com/dotnet/BenchmarkDotNet/pull/2958), [#3235](https://github.com/dotnet/BenchmarkDotNet/pull/3235)). The obsolete `AddPackages` was removed ([#2904](https://github.com/dotnet/BenchmarkDotNet/pull/2904)). The constructor takes the project path, TFM and `ArtifactsPaths` instead of a `GenerateResult`, and `CliPath` is a `FileInfo` ([#2508](https://github.com/dotnet/BenchmarkDotNet/pull/2508), [#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232), [#3256](https://github.com/dotnet/BenchmarkDotNet/pull/3256)).
* The synchronous `BenchmarkRunner.Run`/`BenchmarkSwitcher.Run*` overloads gained an optional `CancellationToken` parameter ([#3213](https://github.com/dotnet/BenchmarkDotNet/pull/3213)). This is source compatible, but code compiled against older versions must be recompiled.
* In-process toolchains ([#2938](https://github.com/dotnet/BenchmarkDotNet/pull/2938)):
  * `InProcessEmitToolchain.Instance`/`InProcessNoEmitToolchain.Instance` → `.Default`.
  * The `(bool logOutput)` toolchain constructors, the timeout, `DontLogOutput`, `Job.InProcessDontLogOutput` and `InfrastructureMode.InProcessDontLogOutput` were removed. Toolchains are created with `InProcessEmitToolchain.From(new InProcessEmitSettings { ... })` ([#3232](https://github.com/dotnet/BenchmarkDotNet/pull/3232)).
  * `[InProcess(bool)]` → `[InProcess(InProcessToolchainType toolchainType = Auto, bool executeOnSeparateThread = true)]`.
  * `[InProcess]`/`--inProcess` now pick the emit or no-emit toolchain automatically.
* `IConfig` gained a `Title` property, so custom `IConfig` implementations must add it ([#3214](https://github.com/dotnet/BenchmarkDotNet/pull/3214)).
